# PixelSteg 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a high-capability, auditable cover-PNG steganography workflow with messages and file bundles, four automatically detected profiles, capacity and quality reporting, optional authenticated encryption, CLI/WPF support, and version-1 compatibility.

**Architecture:** A dependency-free PNG codec normalizes supported covers, a bounded bundle represents messages and files, and a versioned envelope handles compression and AES-GCM. A common locator selects balanced, dense, adaptive, or resilient embedding; CLI and WPF call the same core APIs and keep writes atomic.

**Tech Stack:** C# 12, .NET 8, WPF, `System.IO.Compression`, `System.Security.Cryptography`, xUnit.

**Spec:** `docs/superpowers/specs/2026-09-01-pixelsteg-2-design.md`

## Global Constraints

- Preserve `encode` and `decode` behavior for version-1 containers.
- Accept only 8-bit, non-interlaced RGB and RGBA cover PNGs in version 2.
- Skip every pixel whose alpha is not 255; profiles may use one or two low RGB bits.
- Never overwrite outputs without the existing explicit overwrite path.
- Never open, execute, download, or interpret embedded payloads.
- Do not add runtime NuGet dependencies.
- Tests use only synthetic images and inert payloads.
